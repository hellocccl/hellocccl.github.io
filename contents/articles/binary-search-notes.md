# 二分答案与判定函数笔记

**发布日期：** 2024-05-18  
**标签：** 二分、算法基础、思维技巧

二分不是“有序数组专属技巧”，它更常见的用途其实是：**在答案空间上二分一个满足条件的最优值**。很多题表面上是优化问题，实质上是“猜一个答案，然后判断它能不能成立”。

## 一、什么时候能二分

判断一题能不能二分，最关键看两点：

1. 答案空间是否有序。
2. 判定结果是否具有单调性。

常见单调关系：

- 如果答案 `x` 可行，那么所有 `x' >= x` 也可行。
- 如果答案 `x` 不可行，那么所有 `x' <= x` 也不可行。

这类题通常可以抽象成：

> 找到最小的可行值，或者最大的可行值。

## 二、最常见的两类写法

### 1. 找最小的可行值

适用于“越大越容易满足”的情形。

```cpp
long long l = 0, r = 1e18;
while (l < r) {
    long long mid = l + (r - l) / 2;
    if (check(mid)) r = mid;
    else l = mid + 1;
}
cout << l << '\n';
```

循环不变量：

- `r` 始终落在可行区间。
- `l` 始终落在待确认区间。

### 2. 找最大的可行值

适用于“越小越容易满足”的情形。

```cpp
long long l = 0, r = 1e18;
while (l < r) {
    long long mid = l + (r - l + 1) / 2;
    if (check(mid)) l = mid;
    else r = mid - 1;
}
cout << l << '\n';
```

这里 `mid` 要向上取整，否则会在 `l = mid` 时卡死。

## 三、判定函数怎么设计

二分的难点通常不在二分本身，而在 `check(mid)`。

一个好的判定函数通常具备：

- 含义明确：`mid` 代表什么。
- 复杂度稳定：最好是 `O(n)`、`O(n log n)`。
- 与原题目标严格对应：不要“差不多能判”，而要“完全等价”。

比如：

- 最小化最大值 -> 判定“最大值限制为 mid 时能否完成任务”。
- 最大化最小值 -> 判定“每段至少 mid 时能否切分成功”。
- 最短时间完成 -> 判定“给定 mid 时间能否做完”。

## 四、常见套路

### 1. 二分答案 + 贪心判定

这是竞赛里最常见的组合。

例如“把数组分成若干段，使每段和不超过 `mid`，问最少需要几段”，就可以贪心地从左到右合并。

### 2. 二分答案 + 前缀和判定

用于区间平均值、区间长度限制、最大子段均值等问题。

常见变形是：

- 把原值减去 `mid`
- 判断是否存在某个区间使得新数组区间和非负

### 3. 二分答案 + 图搜索

比如二分边权上限，再用 BFS/DFS/并查集 判断图是否连通。

## 五、边界怎么设

边界设置错误是二分最容易出 bug 的地方。

经验做法：

- `l` 设成一定不优于答案的下界。
- `r` 设成一定覆盖答案的上界。

例如：

- 数组最大值最小化：`l = max(a[i])`，`r = sum(a[i])`
- 时间最小化：`l = 0`，`r = 足够大的时间`
- 长度/值域问题：要认真确认是否允许取 `0`

## 六、容易写错的地方

### 1. `mid` 溢出

不要写：

```cpp
int mid = (l + r) / 2;
```

推荐：

```cpp
long long mid = l + (r - l) / 2;
```

### 2. 开闭区间不统一

如果你一会儿写 `[l, r]`，一会儿又按 `[l, r)` 理解，代码很容易错。

建议固定一套：

- 要么坚持闭区间 `[l, r]`
- 要么坚持左闭右开 `[l, r)`

### 3. 判定函数不是单调的

这是本质性错误。  
一旦 `check(mid)` 本身不单调，二分就没有正确性保证。

### 4. 忘记答案可能不存在

如果题目不保证有解，需要在二分前后补一层判断。例如先判断 `check(r)` 是否成立。

## 七、一个典型例子

题意：给定数组和整数 `k`，把数组分成不超过 `k` 段，最小化每段和的最大值。

思路：

1. 答案越大越容易分段成功，具有单调性。
2. 二分每段最大允许和 `mid`。
3. 贪心统计在限制为 `mid` 时最少需要多少段。
4. 若所需段数 `<= k`，说明 `mid` 可行。

判定模板：

```cpp
bool check(long long mid) {
    long long cur = 0;
    int cnt = 1;
    for (int x : a) {
        if (x > mid) return false;
        if (cur + x <= mid) cur += x;
        else {
            cnt++;
            cur = x;
        }
    }
    return cnt <= k;
}
```

## 八、做题时的思考顺序

我通常按下面顺序判断：

1. 题目问的是“最大值最小”还是“最小值最大”？
2. 能否猜一个答案 `mid`？
3. 猜了以后，是否能在线性或对数复杂度里判断？
4. 判定结果是否单调？
5. 应该找最小可行值还是最大可行值？

如果这五步能顺下来，这题大概率就是标准二分答案。

## 九、结语

二分真正重要的不是模板，而是把优化目标转成判定问题的能力。很多题第一次看像 DP、贪心甚至图论，最后落点却是“二分一个答案再判”。

把“答案空间 + 单调性 + 判定函数”这三件事想清楚，二分题会稳定很多。
