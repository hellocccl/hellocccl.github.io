# 背包 DP 总结：01、完全、多重、分组

**发布日期：** 2025-06-11  
**标签：** 动态规划、背包DP、算法笔记

背包问题看起来类型很多，但核心框架非常统一：**枚举物品，更新容量状态**。真正难的是分清楚不同模型的转移方向和状态含义。

## 一、最基本的状态定义

通常设：

```text
dp[j] = 容量为 j 时能取得的最大价值
```

如果题目不是求最大价值，也可能是：

- 最小代价
- 是否可达
- 方案数

但状态骨架经常一样。

## 二、01 背包

每个物品最多选一次。

转移：

```text
dp[j] = max(dp[j], dp[j - w] + v)
```

关键点：**容量从大到小枚举**。

```cpp
for (int i = 1; i <= n; i++) {
    for (int j = m; j >= w[i]; j--) {
        dp[j] = max(dp[j], dp[j - w[i]] + v[i]);
    }
}
```

为什么倒序？

- 防止同一件物品在一轮里被重复使用。

## 三、完全背包

每个物品可以选无限次。

转移式看起来一样：

```text
dp[j] = max(dp[j], dp[j - w] + v)
```

但关键点变成：**容量从小到大枚举**。

```cpp
for (int i = 1; i <= n; i++) {
    for (int j = w[i]; j <= m; j++) {
        dp[j] = max(dp[j], dp[j - w[i]] + v[i]);
    }
}
```

因为完全背包允许当前物品在本轮被重复利用。

## 四、多重背包

每个物品最多选 `c[i]` 次。

处理方式有两种：

### 1. 朴素做法

枚举选几件，复杂度通常偏大。

### 2. 二进制拆分

把 `c` 拆成若干个 `1, 2, 4, ...` 的组合。

例如 `13 = 1 + 4 + 8`，就把一件物品拆成多件 01 物品：

- 重量 `1 * w`
- 重量 `4 * w`
- 重量 `8 * w`

这样复杂度会降很多。

```cpp
for (int i = 1; i <= n; i++) {
    int cnt = c[i];
    for (int k = 1; k <= cnt; k <<= 1) {
        items.push_back({k * w[i], k * v[i]});
        cnt -= k;
    }
    if (cnt) items.push_back({cnt * w[i], cnt * v[i]});
}
```

之后按 01 背包做。

## 五、分组背包

每组里最多选一个物品。

转移：

```cpp
for (每一组 g) {
    for (int j = m; j >= 0; j--) {
        for (组内每个物品 item) {
            if (j >= item.w) {
                dp[j] = max(dp[j], dp[j - item.w] + item.v);
            }
        }
    }
}
```

本质上是“每组只能贡献一次转移”。

## 六、循环顺序是背包题的灵魂

我做题时会先记这张表：

| 模型 | 容量枚举方向 |
|------|--------------|
| 01 背包 | 从大到小 |
| 完全背包 | 从小到大 |
| 多重背包（二进制拆分后） | 从大到小 |
| 分组背包 | 从大到小 |

如果方向错了，代码大概率错。

## 七、背包题常见变形

### 1. 恰好装满

初始化时不能全设为 0，而要设成负无穷，只保留：

```cpp
dp[0] = 0;
```

### 2. 求方案数

把 `max` 换成加法，但要小心去重顺序。

### 3. 价值维背包

如果容量很大、价值总和较小，可以反过来设：

```text
dp[v] = 达到价值 v 的最小代价
```

### 4. 二维费用背包

状态变成：

```text
dp[j][k]
```

思路不变，只是容量维度多了一层。

## 八、做题时如何识别模型

我一般先问自己：

1. 每个物品能选几次？
2. 是不是有“组”的概念？
3. 是求最大值、最小值还是方案数？
4. 是不是要求恰好装满？

这四个问题基本就能定位模型。

## 九、常见坑

### 1. 初始化错

“是否可达”和“最大价值”初始化方式不同，尤其是恰好装满模型。

### 2. 循环顺序错

这是背包题最常见 bug。

### 3. 多重背包复杂度没控住

数据大时不要硬做三重循环。

## 十、结语

背包题真正该掌握的是“物品是否可重复使用”和“状态是否允许本轮继续转移”这两个核心逻辑。只要这两个点想清楚，很多变形都只是套一层外壳。
